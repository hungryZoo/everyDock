- 자동 회귀 **PASS**: `swift test --arch arm64` 25개. 기존 17개와 새 매칭·메뉴 좌표·레이블·일괄 닫기 순서 8개.

- Finder 포함 모든 창 닫기, 카드 ×, 메뉴에서 직접 열린 창 보기, 팝업 닫힘 후 대상 초기화 구현.
- 실제 앱 창 호환성·모든 edge·저장 확인 행렬·이번 빌드의 프레임 성능은 아직 전체 검증하지 않았다. 닫기 자동 테스트는 제어 순서만 검사하며 실제 사용자 문서를 닫지 않았다.
- 실제 실행·배포 검증 결과는 아래에 추가한다. 미실행 항목을 PASS로 계산하지 않는다.

## 실기기 테스트 방법

`./scripts/window-fixture.sh`로 테스트 앱을 빌드하고 출력된 `open` 명령으로 실행한다. [WindowFixture](../Tests/Fixtures/WindowFixture.swift)는 같은 제목의 빈 창 3개를 만들며 각 창에 1/2/3 식별 문구가 있다. 파일·설정·네트워크를 사용하지 않는다. ‘Require save confirmation’ 체크박스는 실제 저장 없이 저장 확인 sheet를 모사한다. 실제 사용자 문서 대신 이 창에서 카드 선택·×·모든 창 닫기·취소를 시험한다. 테스트 종료는 앱의 Dock 메뉴 ‘종료’를 이용한다.

## 실제 실행 결과

환경: Apple M5, macOS 26.5.2, 외장 60Hz와 내장 120Hz의 기존 설정. 최종 패키지 실행 파일 SHA-256은 `10acb28a2b4b6f89638a5a09eb5e545bb03549413055433cfdb9b241319fddb0`이다.

- **PASS (관찰 범위)**: 최종 앱의 AX/SCK 실제 접근 복구 후 WindowFixture 동명 창 3개가 서로 다른 이미지와 함께 정확히 3개로 표시됐다. 중간 카드 ×로 2번 창만 닫고, 3번/1번 창과 2개 표시가 남았다. 1번 카드를 선택하자 실제 1번 창이 전면에 표시됐다.
- **PASS (관찰 범위)**: fixture의 저장 확인 모드에서 ‘모든 창 닫기’가 저장 확인 sheet를 표시했다. 취소 후 두 창이 그대로 보존됐다. 확인 모드를 해제하고 다시 모든 창 닫기를 실행하자 0개 창으로 표시되고 앱 프로세스는 계속 실행됐다.
- **PASS (관찰 범위)**: 같은 앱에서 메뉴→미리보기→카드 선택→메뉴→미리보기 재개방을 반복했다. Finder 메뉴에도 ‘모든 창 닫기’와 ‘열린 창 보기…’가 표시됐다.
- TC-M34/M37 **PARTIAL**: 메뉴 좌표와 레이블 중앙 배치는 자동 테스트로 검증했으며 모든 edge·1×/2×·라이트/다크 시각 행렬은 미실행이다.
- TC-M35/M38/M39/M40 **PARTIAL**: 위 fixture 경로는 통과했지만 Chrome/Finder 전체 창 조합, 실제 문서 저장 확인과 새 창 생성 중 일괄 닫기 행렬까지 확장하지 않는다. 사용자 창을 일괄 닫는 실험은 하지 않았다.
- TC-P01~P03 **NOT RUN (이 버전)**: 기존 NSControl·캐시·display link 경로를 유지했으나 이번 빌드의 실제 표시 프레임/CPU 수치 목표는 새로 측정하지 않았다.

- Finder 추가 대조 **PASS (관찰 범위)**: everyDock의 4개 카드가 Finder 자체 ‘윈도우’ 메뉴의 4개 항목과 일치했다. 동명 폴더 창 2개도 양쪽에 독립 항목으로 존재했다. 기존 Finder 창을 닫거나 폴더 위치를 바꾸지 않았다. 빈 Finder에서 다시 열기(TC-M36)는 이 회차에서 **NOT RUN**이다.
